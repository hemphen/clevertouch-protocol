# Instructions for contributors and coding agents

This repository is the protocol specification. It holds no code.

## Content

- State protocol facts only: layouts, values, rules, timings, open questions.
- Label every claim that is not plain layout: **Observed**, **Client**,
  **Strong**, **Tentative** or **Unknown** ([definitions](docs/common.md#evidence-labels)).
- Give at most one headline count as the basis, e.g. "Observed: 128 of 128".
  The experiments, captures and reasoning behind a claim live in the private
  research repository, not here.
- Use synthetic identifiers only. Never add RF addresses, cloud IDs, MAC
  addresses, cursors, tokens, coordinates or household recordings.
- Do not add security findings about the provider's service. They stay in the
  private research repository until the owner decides on disclosure.
- `docs/radiator-rf/vectors.json` is generated by radiator-rf's
  `tools/make_vectors.py`. Change it there and copy it here; never edit it by hand.

## Style

- Short, plain sentences in the present tense. Describe the protocol as it is,
  not how it was found.
- Tables for fields and values, numbered lists for procedures, mermaid for
  message sequences.
- Put each fact in one place and link to it. Shared values live in
  `docs/common.md`.
- Tags in upper-case hex (`8A`); bytes as spaced hex (`19 00`); frames as
  unspaced hex. Temperatures as raw value and °C.
- Message names: `radiator_report`, `controller_state`, `request`, `ack`,
  `inclusion_offer`, `inclusion_reply`, `inclusion_bind`, `unknown`.
- Keep heading anchors stable; other repositories link to them.

## Changes

Add a [CHANGELOG.md](CHANGELOG.md) entry for any change an implementation must
follow: a new or reinterpreted field, a renamed message or output field, a
changed rule or vector.
